We built Terminal Session Profiles because agent tools like Claude Code turned our terminals into long-lived, named parts of every project, while VS Code's own persistence was scattered across profiles, tasks, and settings. This brings it into one place: save a terminal setup as a reusable profile, and get it back, still running and in the right directory, after a restart. It is the workflow we use daily for our own named Claude sessions, dev servers, PowerShell, and WSL terminals.
